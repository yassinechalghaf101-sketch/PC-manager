01

What it is

deepcode is a single-file, terminal-only coding harness. You type a request at YOU ›; it plans with tools, reads and edits real files, runs PowerShell, checks the result, and answers. It keeps a continuous conversation and writes every turn to a JSONL session log.

Shape

One file, zero installs

deepcode.py is 1,830 lines of Python using only the standard library. No pip, no Node, no build step, no TUI library. The UI is ANSI text.

Default engine

Local Ollama

Talks to http://127.0.0.1:11434 with the native /api/chat API, so it controls context size, threads, output length, batching, and keep-alive.

Optional engine

Any OpenAI-compatible API

Point --api at a base URL ending in /v1 and pass --key. DeepSeek, OpenRouter, LM Studio, and similar endpoints use the same tool schemas.

Permissions

Full disk, auto-run

No path clamp and no confirmation prompts. File tools reach the whole disk; shell runs as the current user. This is a deliberate choice, and the main risk.

The core bet: a small local model plus a tight tool loop, a strict prompt, and verification can do real coding work without a cloud account — as long as the context window and the tool output are kept under control.

02

The loop

Every request goes through the same five-stage cycle. There is no finish() tool: a reply with no tool calls is the final answer.

1

Take the task, trim the history

Harness.run_turn() appends the user message and immediately trims the conversation to the context budget. The current task is always preserved; the oldest whole turns go first.

2

Ask the model

client.chat() sends the system prompt, history, and all seven tool schemas. Ollama streams NDJSON chunks and Ctrl+C stops generation; the OpenAI path is a normal request/response call.

3

Read the reply

The reply carries text, optional reasoning, and zero or more tool calls. No tool calls means the turn is done: the answer is printed, logged, and control returns to YOU ›.

4

Execute tools, feed results back

Each call is validated and run in order. The observation is clipped, appended as a tool message, and the loop calls the model again. Multiple calls per reply are allowed.

5

Stop on an answer or a guard

A normal answer ends the turn. Caps stop runaway work, and an empty reply is retried once after a harder trim; a second empty reply becomes a visible error instead of silence.

Guardrails

Steps--max-steps 60 model turns per request.
Wall clock--max-minutes 20, checked before each step. 0 disables it.
RepeatsThe third identical tool call is refused with an error result.
Empty replyTrim to half budget, retry once, then report prompt tokens and done_reason.
ContextHistory is char-budgeted from --ctx; tool output is clipped adaptively.
Tool callsBad arguments become an error observation, not a crash.

04

The seven tools

The model sees the same JSON schemas on every backend. Inputs are checked centrally; a bad call returns an error string and the loop continues.

ToolWhat it doesLimits and behavior
shellRuns PowerShell 5.1 as the current user. Full disk; can build, test, git, and install.New process per call; workdir; timeout 120 s default, 600 s max. Only the shell is killed on timeout — grandchildren may survive. UTF-8 is forced on redirected output.
list_dirLists directories first, then files with sizes.Non-recursive by default; recursive walks cap at 500 entries and skip .git, node_modules, caches, and build output.
read_fileReads UTF-8 text with 1-based line numbers for reference.300 lines by default, 2,000 hard cap; offset and limit. Line-number prefixes must not be copied into edit_file.
write_fileCreates or overwrites a text file; parent directories are created.Overwrites are permanent. Returns the character count and resolved path.
edit_fileReplaces exact text; shows a compact diff in the terminal.Fails if the old text is absent or occurs more than once, unless replace_all is set. Empty old is rejected.
search_filesSearches file contents with a regular expression and optional filename glob.Case-sensitive by default ((?i) to change); caps at 5,000 files, 100 matches, 1 MB per file; skips binaries and heavy directories.
update_todoReplaces the visible checklist for multi-step work.Max 12 items; statuses pending, doing, done; the UI redraws the list after each update.
Path handling

Absolute, relative, or aliased

Relative paths resolve against --workspace; absolute paths are used as given. ~ and %VAR% expand. If OneDrive redirected the Desktop, writes to C:\Users\<you>\Desktop are remapped to the real folder — for file tools, shell text, and workdirs.

Failure model

Errors are observations

Unknown tools, invalid JSON arguments, missing files, and OS errors become ERROR: … strings in the transcript. The model can read the error and try a different approach; one bad call never ends the session.

05

Context, speed, and heat

A 4B model on a 4 GB laptop GPU is the constraint that shapes the whole design. Everything here exists to keep the prompt inside the window and the CPU from cooking.

The history budget

The budget is computed once per launch from the context window, then enforced before every turn:

reserve        = min(--max-predict, 1024)
tool_schema    = len(json.dumps(TOOL_SCHEMAS))       # ~3,815 chars
history_budget = max(1500, int((ctx - reserve) * 2.8) - tool_schema)
# ctx 4096 → 4,786 chars for system + conversation

Trim order

Cheap cuts first

1. Any tool message over 1,500 chars is shortened to an 800-char head plus a 400-char tail. 2. If still over budget, the oldest whole turns are deleted up to the current task. The current request is never removed.

Tool output

Adaptive clipping

min(6,000, max(1,500, ctx × 0.75)). At the default 4k context that is 3,072 chars; at 8k it reaches the 6,000 cap. The full observation still goes to the session log.

Caching

Append-only by default

The system prompt is static and history is append-only, so Ollama reuses its prompt prefix between steps. Trimming, /new, and --resume start a fresh prefix.

Failure mode

Empty reply = overflow or silence

If the prompt fills the window, the model can stop with no answer. The harness trims once and retries, then reports prompt tokens and done_reason instead of printing nothing.

14.9–17.0 tok/s

Short doctor runs at 8 threads. Real coding steps land around 12–14 tok/s once prompts grow.

Memory

GPU 50% · CPU 50%. The 4 GB RTX 3050 cannot hold the weights plus the KV cache, so Ollama splits layers.

Load

The heat is Ollama's split, not the Python. The harness can cap threads, output, and time, but it cannot move more of a 3.7 GB model into 4 GB of VRAM. If it runs hot: --threads 6 or 4, a smaller model such as qwen3.5:2b (1.9 GB, fully on GPU), or a remote API. There is no CPU temperature sensor exposed to the harness.

06

Sessions and resume

Every message, tool call, and observation is appended to a JSONL transcript. Logs are for replay and debugging — they are not backups.

// sessions/2026-11-14T12-05-05.jsonl (one JSON object per line)
{"kind":"start","model":"qwen3.5:4b","backend":"ollama",...}
{"kind":"message","message":{"role":"user","content":"fix buggy.py"}}
{"kind":"task","task":"fix buggy.py"}
{"kind":"assistant","step":1,"content":"","tool_calls":[...]}
{"kind":"tool","name":"read_file","args":{...},"observation":"..."}
{"kind":"done","content":"The test passes."}
{"kind":"end"}
Resume rules

Latest means latest usable

--resume without a path scans newest-first and skips empty logs left by /new. An explicit path is used as given. A trailing tool result and its assistant tool-call group are dropped if the process died mid-call.

Continuity

History is restored, prompt is refreshed

The saved conversation is loaded, then the current system prompt replaces the old one — so workspace, date, Desktop path, and AGENTS.md reflect this launch. New records append to the same file.

Commands

/new, /exit, Ctrl+C

/new closes the log and starts a fresh session; same-second collisions get a -2 suffix. /exit or /quit leaves. Ctrl+C aborts the current step and returns to the prompt.

Shutdown

The model is unloaded

Harness.close() logs the end and sends keep_alive: 0 to Ollama. Verified: /api/ps reports no loaded models after exit.

07

Safety model

This harness is intentionally unrestricted. It is built for one user on one laptop, not for untrusted input.

By design

No clamp, no prompt

File tools reach the whole disk and shell runs as you. The model executes what it emits. There is no approval step and no dry-run mode.

Consequence

No undo

write_file overwrites permanently; shell can delete anything you can delete. Session logs record what happened, but they cannot restore files.

Exposure

Logs can contain secrets

Commands, environment-dependent output, and file contents can land in sessions/*.jsonl. Treat the folder as sensitive; it is git-ignored, not encrypted.

Edges

Known limits

Timeout kills the shell, not its grandchildren. Shell Desktop remapping is textual, so %USERPROFILE%\Desktop or forward-slash spellings can bypass it. The model can still make wrong choices.

Practical rule: run it in a git repository or a scratch folder, commit before a risky task, and keep --workspace pointed at work you can afford to lose. “Full disk” means full disk.

Case study — the silent empty reply. A session with one prior “hi” turn and a 6,000-char file read reached 4,082 prompt tokens of 4,096. The model had 14 tokens left, emitted thinking markers, and stopped with done_reason: length. The old 12,288-char budget was almost the entire window and trimming never ran before a new turn. The fix: derive the budget from ctx and max-predict, trim before each turn, clip tool output by context, and retry an empty reply once with a real diagnostic.

09

Potential

The harness is deliberately small. The highest-leverage work from here is not more features — it is less risk, better context, and more verification. These are ordered by payoff, not novelty.

Now · hours

Close the honest gaps

  • Test Ctrl+C on a real terminal, including during tool execution.
  • Live-test the OpenAI/DeepSeek path with a key; stream SSE and cancel.
  • Log prompt_tokens and done_reason on every step.
  • Add --ctx presets: cool (4k/8), balanced (8k/12), long (16k/8).
  • Turn the trim and Desktop-remap cases into explicit self-checks.
  • git init and a first commit, so the agent has an undo boundary.
Next · days

Make the agent smarter

  • Repo map: tree plus symbol index and file summaries; retrieve instead of blind reads.
  • Patch edits: unified diffs for small, reviewable changes.
  • Compaction: summarize old turns instead of deleting them.
  • Approval modes: --read-only, --ask, and a sandbox profile.
  • Process-tree kill on timeout, so builds and tests do not survive.
  • Config file and named sessions; a token/cost meter in the footer.
Later · weeks

Turn it into a platform

  • MCP client for external tools and data sources.
  • Subagents for exploration and review with separate contexts.
  • Editor integration through a small local server.
  • Local embeddings for semantic search over the repo.
  • Cross-platform shell layer for macOS and Linux.
  • Packaging, signed releases, and a proper TUI with a diff pane.

Highest leverage, ranked

  1. Approval and sandbox modes. The biggest risk reducer. It makes “full disk by default” a choice instead of a property, without taking capability away from users who want it.
  2. Repo map and symbol search. The biggest quality jump for a 4B model. Most wasted steps are blind reads; retrieval would cut tokens, time, and heat at once.
  3. Streaming remote API and cancellation. Brings the OpenAI-compatible path to parity with local Ollama and makes Ctrl+C predictable everywhere.
  4. Process-tree kill on timeout. A timed-out npm test or build should not leave children running after the harness moves on.
  5. Context compaction. Summaries preserve decisions and file names that trimming otherwise throws away, which is what long sessions need at 4k.
Hard limits

What code cannot fix

The 4 GB VRAM split is hardware; only a smaller model or a remote API changes it. A 4B model will still misread files and choose the wrong tool. No thermal sensor is exposed, so thread caps are a proxy, not a control loop. Full disk is the product — any safety must be opt-in.

Design rule

Judge it by verification

The next version should be judged by how often it runs the test, not by how much it can do. A smaller tool set with hard checks beats a larger one that claims success. Keep the standard library constraint: every dependency raises the install cost and shrinks the places this can run.

Most of the gap between this and a polished agent is context engineering, not model size. The loop is already correct; the next wins are making it see less, remember better, and ask before the irreversible step.
